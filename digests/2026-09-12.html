🆕 What's New

Claude Code v2.1.270 — Bug fix: read-only git commands in Bash were unexpectedly asking for permission after a long session, a regression introduced in v2.1.269. If you use auto mode for extended coding sessions, this one's worth picking up — read-only git introspection (status, log, diff) is a core pattern for multi-step agentic work and the interruption was disruptive.

📄 Docs Changes

Two updates shipped September 10:

  • Claude Managed Agents — auto permission policy: The server now evaluates each agent or MCP tool call and can run it, deny it, or pause for your approval. The agent.tool_use and agent.mcp_tool_use events report evaluation results in a new evaluation field — useful for auditing what your agents are actually doing.
  • ant CLI — session connection: New ant beta:sessions connect command lets you attach your terminal to a live Managed Agents session to follow along, send messages, and approve/deny tool calls in real time. Add --web to serve the Console session viewer locally instead.

💡 Tip of the Day — #14

Extended thinking for hard problems: On Sonnet and Opus models, Claude can reason step-by-step before giving you an answer. This is the mode to reach for on architecture decisions, security reviews, and subtle debugging. Use --model opus in Claude Code for maximum reasoning depth. You'll see the thinking in a collapsible block before the response.

👀 Have You Seen? — Tool Use / Function Calling

Claude can call your defined tools as part of its reasoning. You define a set of functions (database lookups, API calls, calculations, internal services), and Claude will invoke them mid-response when relevant — then incorporate the results before finishing its answer.

This is how you build Claude agents that actually do things: query your data, call your APIs, check live state. It's also the foundation under Claude Code's own file editing, bash execution, and search tools. The Tool Use docs have a quickstart with JSON schema examples for defining your first tool.
